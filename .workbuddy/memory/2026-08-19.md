### 同步删除语义澄清（用户问"目标/项目到任务的删除是否同步"）
- 上云同步只覆盖 Tier 1 热数据（tasks + meta）。**任务删除会同步**（`useTasks.deleteTask` → `syncState.markTaskDeleted(id)`，云端 `/sync` 精确删 `source='qg'` 行）。
- **项目/目标删除不同步**（Tier 3 冷数据，从未上云），且 `deleteProject`/`deleteGoal` 不级联删其下任务 → 已同步的任务仍留本地+云端（只失去归属）。
- **已知小 bug**：删带子任务的父任务时，本地把父+子（`parentId===id`）一并删，但 `deletedTaskIds` 仅含父 id（`markTaskDeleted(id)`），云端 `/sync` 不级联 `parent_id` → 云端子任务行残留。修复方向：deleteTask 把子任务 id 也 markTaskDeleted（云端无需改）。
- 待用户定方向：是否做"删项目/目标级联清其下任务（含云端）"——需前端级联 markTaskDeleted + 云端 /sync 加 parent_id 级联删。

### 方案A（去本地 server，纯本地架构）完成
- **决策**：本地不再需要开 Express/SQLite 后端。api 层改写为「本地持久化适配器」，直接读写 hooks 已用的同一组 localStorage key（`__quest_guild_*`），hooks 零改动（它们本来就是先写本地、再 await api 镜像）。Electron 端持久化本来就走 electron-store IPC，server 只是镜像，删除后无影响。

- **验证**：`node --check` main/preload、`tsc`、`vite build`、`scripts/build-renderer.mjs` 全绿；bundle grep：`localhost:3001|api:proxy`=0、`api/tasks/sync`=1、`life.hchch.tech`=1、`纯本地模式已下线`=1。
